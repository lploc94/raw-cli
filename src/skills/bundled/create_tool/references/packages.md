# Share tools and variable providers as Raw packages

Use `examples/packages/tool-only/` for a standalone tool and `examples/packages/mixed-kit/` for a tool with a helper, executable variable provider and agent. `raw-package.json` declares a scoped package name, SemVer release label, explicit owned `files`, and exports. A tool export points to its folder; that folder contains `tool.json`, `index.mjs` and every relative helper/resource import. A variable provider export is one JSON definition under `var_providers/`; its script must also be in `files`. There are no install hooks or automatic npm/pip/system dependency installers. Declare external prerequisites and recipient paths as typed inputs.

Run `raw package validate DIR` and fix undeclared helpers, symlinks or missing exports. `raw package pack DIR --out FILE.rawpkg` creates a reproducible bounded archive. The recipient uses `raw package install FILE.rawpkg --as ALIAS --config CONFIG`, then selects `pkg/ALIAS/tools/EXPORT` in a direct agent or binds `var_providers.NAME={"from":"pkg/ALIAS/var_providers/EXPORT","inputs":{}}`. A tool object selection may add `as` for a distinct model-visible name. Policy matches `@owner/name#tools/EXPORT`, independent of the installation alias or release label.

Use `loadConfig({configPath,requireModel:false})` and `createRuntimeTools({runtime,cwd})` to validate the selected schema and dispatch a harmless call, closing MCP connections afterward. For a provider, use `raw vars list` then a readable `raw vars get NAME` to exercise its one-request JSON protocol. Installation and validation are data-only; they do not import handlers, run providers, connect to MCP or call a model. `raw package link DIR --as dev` snapshots helper bytes at the next runtime; a running handler retains its old snapshot. Updates preserve local inputs/overrides and current sessions; a real helper/schema edit rotates the generated key once, while a release label alone does not.
