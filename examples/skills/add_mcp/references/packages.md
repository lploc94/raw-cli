# Bind or share an MCP definition through a package

`examples/packages/mixed-kit/` has a complete `mcp/search.json` export and its declared stdio script. A standalone package may export one server definition under `exports.mcp.SERVER`. Each export file contains one current Raw MCP server definition. Declare executable assets in `files`; use typed package inputs for recipient-specific endpoint, header, environment name or command arguments. An input replaces an entire approved value site; `${VAR}` interpolation in strings is not supported.

Author: run `raw package validate DIR` and `raw package pack DIR --out FILE.rawpkg`. Recipient: `raw package install FILE.rawpkg --as ALIAS --config CONFIG`; bind a local name with `"mcp":{"servers":{"web":{"from":"pkg/ALIAS/mcp/SERVER","inputs":{...}}}}`, then select exact `mcp/web/ORIGINAL_TOOL` IDs in the agent's ordered `tools.use`. The local `web` name controls the stable model-facing alias. Package policy matches the canonical `@owner/name#mcp/SERVER/ORIGINAL_TOOL`, including conditional ask rules; release labels and artifact hashes are not alias names.

`raw config list` validates the binding structure but does not prove a live handshake. Use `loadConfig({configPath,requireModel:false})` plus `createRuntimeTools({runtime,cwd})` to check discovery/schema and call a harmless selected tool, then close the MCP connection. An unselected server stays inert. `package update` changes the next runtime attachment and checks current binding inputs; an old saved session can resume with the current server. Do not clear sessions, silently substitute tool names or infer an endpoint/credential the user did not provide.
