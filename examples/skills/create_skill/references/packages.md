# Share a skill as a Raw package

Use `examples/packages/skill-only/` in the installed Raw package as a complete source example. The source contains `raw-package.json` with `schema_version:1`, a scoped `name`, SemVer `version`, nonempty `description`, `files:["skills/repo-review"]`, and `exports.skills.repo-review:"skills/repo-review"`. `skills/repo-review/SKILL.md` has matching Agent Skills YAML frontmatter; `references/checklist.md` is declared through the directory file closure. A loaded skill body does not automatically load that reference; tell the agent when to read it with `read_file`.

To author a new skill package, copy the layout to a new folder, replace the skill name, description and body, update the manifest export/path, and declare all supporting files. Run `raw package validate DIR`, inspect reported files/exports, then `raw package pack DIR --out FILE.rawpkg`. The recipient runs `raw package install FILE.rawpkg --as ALIAS --config CONFIG` and adds `pkg/ALIAS/skills/EXPORT` to an existing agent's `skills.use`. If another selected skill already uses the same name, select `{"ref":"pkg/ALIAS/skills/EXPORT","as":"unique-name"}`. Keep `builtin/list_skills` and `builtin/load_skill` in `tools.use`.

Verify the exact selected name and body with `list_skills` then `load_skill`, or with `loadConfig({configPath,requireModel:false})` plus `loadSelectedSkills`/`createRuntimeTools`. `config list` alone does not load the skill. For local development, `raw package link DIR --as dev --config CONFIG` snapshots the current source for each new runtime; an edit appears on the next run/resume. A changed previously visible skill can produce a tail reload notice, and the agent should list/load again. Do not clear a session merely because its skill changed. Never embed runtime secrets or current readings in skill Markdown.
