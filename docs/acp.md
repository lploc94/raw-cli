# Agent Client Protocol

Selected agent hooks run through the same session and tool boundaries as CLI and dashboard. ACP sends each hook receipt as an `agent_thought_chunk` update and replays it from visible history on session load. Hook status is not added to the model conversation. See [hooks](hooks.md).

`raw --acp --stdio` runs an ACP v1 agent over newline-delimited JSON-RPC on stdin/stdout. Stdout contains protocol messages only; diagnostics go to stderr. `raw --acp` defaults to stdio. `raw --acp --ws --host 127.0.0.1 --port 8765` serves one JSON-RPC object per WebSocket text frame, with a 16 MiB frame limit. The WebSocket server binds only loopback and rejects browser `Origin` and binary frames. This mode is for local IDE/parent processes, not public hosting.

Standard clients call `initialize`, `session/new`, then `session/prompt`. Raw sends `session/update` chunks/tool statuses and replies to `session/prompt` only after the turn ends. A batch remains one model tool call and one ACP `toolCallId`; its `rawInput` contains the input array and its `rawOutput` contains indexed results for every entry. `session/cancel` can interrupt inference, MCP calls, reverse callbacks and Bash; active batch entries finish or cancel under their tool contract, and later entries are skipped. Tools execute automatically in ACP sessions; library callers can explicitly enable permission callbacks. The default three model tools remain `read_file`, `write_file`, `bash`; ACP methods and slash commands do not become model tools. Raw advertises ACP version 1, text and `resource_link` prompt support, SSE and HTTP MCP support, `loadSession`, and `sessionCapabilities.list/resume/delete`; optional prompt image/audio/embedded-resource capability remains absent.

Sessions are saved in the private global store. `session/list` returns at most 20 recent sessions and an opaque `nextCursor`; optional `cwd` filters by the exact workspace. `session/load` takes the saved session ID, matching absolute `cwd`, and current `mcpServers`, replays committed visible history through ordered standard `session/update` notifications, then permits another prompt. `session/resume` attaches to that session without replay and permits another prompt. The saved active model context is restored for both; old reverse-tool callbacks never run from history. `session/delete` permanently removes an inactive session. Unknown, expired, busy, and cwd-mismatched sessions return explicit errors before tool execution. Sessions expire after thirty days without committed activity by default.

Each ACP peer owns its attached runtime and writer claim. `session/cancel` stops only the current operation, so the same peer can prompt again; another peer cannot write that session until the first disconnects. Disconnect aborts active work, settles committed writes, closes MCP clients, and releases the claim while retaining the saved session. Resuming uses the current agent and reconnects its selected MCP servers. A saved explicit `_raw/session/configure` view remains active while the base selection is unchanged; unavailable historical aliases are removed from that view. Changing the base selection uses the current selection instead. Changed available tool definitions advance the context revision and rotate Raw's generated cache key. A callback alias registered by a former peer is removed from the active tool view on resume, rotates that key, and can be registered afresh by the new peer. Historical callback output remains visible in replay, but its old handler is never invoked. Changed model, endpoint, and effective system prompt create a new runtime generation on the same session ID.

`session/new` requires an existing absolute `cwd`. It accepts standard MCP server definitions as explicit session selections. The selected agent's configured MCP map supplies other initial selections; unselected configured servers do not start. Every selected or ACP-injected tool obeys the agent's ordered allow/ask/deny rules, matched on canonical identity. An explicit `ask` uses `session/request_permission` and cannot be bypassed by `-y`. A server's discovery data is never added to model instructions. Cwd changes how relative file paths resolve; it does not confine Bash or create an OS sandbox.

Prompt blocks may contain text and `resource_link` in any order, including only resource links. Raw keeps their type and supplied metadata in the transcript. The provider receives each link as a concise labeled user reference containing its URI/name and supplied title, description, MIME type, size and annotations in order; raw does not fetch or read the URI. Unsupported optional prompt blocks return an explicit error if their capability was not advertised. Tool-result images follow the native provider mapping documented in [MCP](mcp.md); client prompt images are not advertised in v1.

## Raw extensions

The initialization `_meta.raw` object advertises `runtimeInfo`, `sessionConfigure`, `toolRegister`, `toolCall`, and `sessionCompact` booleans. A client advertises its supported raw booleans in its own initialization `_meta.raw`; unknown fields are ignored, known fields must be booleans. Standard ACP works without any raw negotiation. Extensions use underscore-prefixed methods and never replace standard ACP methods.

| Method | Request | Result |
|---|---|---|
| `_raw/runtime/info` | `{ "sessionId"?: string }` | Redacted agent/model, limits, exposed tool aliases/origins and discovered MCP alias catalog |
| `_raw/session/configure` | `{ "sessionId": string, "tools": string[] }` | `{ "contextRevision": number, "tools": string[] }` |
| `_raw/tool/register` | `{ "sessionId": string, "name": string, "description": string, "inputSchema": object }` | `{ "toolId": string, "alias": string, "contextRevision": number }` |
| `_raw/tool/call` (agent to client) | `{ "sessionId": string, "toolId": string, "invocationId": string, "arguments": object }` | `{ "isError": boolean, "content": ToolContent[] }` |
| `_raw/tool/cancel` (agent to client notification) | `{ "sessionId": string, "invocationId": string }` | No response |
| `_raw/session/compact` | `{ "sessionId": string }` | `{ "status": string, "beforeBytes"?: number, "afterBytes"?: number, "usage"?: object }` |

`ToolContent` is `{type:"text",text:string}`, `{type:"json",value:JSON}`, or `{type:"image",mimeType:"image/png"|"image/jpeg",data:"BASE64"}`. Registration supplies a schema, never JavaScript source or a command path. A tool call travels back over the same connection to the owning client; the returned content enters the next model request through the ordinary tool-result path. Registration/configuration require an idle session. `_raw/runtime/info` reports the selected agent, model alias/ID, method, vision, limits, configured MCP selection, tool rules, exposed tools and discovered MCP aliases with `exposed` status; credentials are omitted. `_raw/session/configure` can select an already discovered alias for a later turn. Unknown names, duplicate names, invalid schemas, missing capability, timeout, cancellation and late replies have explicit errors. Callback timeout or disconnect aborts the pending reverse request. `_raw/session/compact` uses the same atomic operation as the library and REPL; it cannot override the configured compact agent per request. Agent-triggered automatic compact emits ACP `agent_thought_chunk` progress updates.

A peer that advertises `_meta.raw.panelsV2: true` may register a tool with an optional `panels` array (declarations as in [tools](tools.md), at most four) and return `{"type":"panel", "panel":"<id>", "op":..., ...}` items in `_raw/tool/call` results. Without that capability a panel item is rejected as `unsupported_content`, as before. The agent advertises `panelsV2: true` too. Panels are validated, stored and shown by the same host as every other source ([panels design](panels-design.md)); Each committed update of a panel declared with `acp_plan: true` also sends a standard `session/update` `plan` (the first checklist flattened depth-first; `done` and `skipped` map to `completed`, `blocked` and `failed` to `pending`, priority defaults to `medium`), and a client that negotiated `panelsV2` additionally receives the `_raw/panel/update` notification `{ sessionId, panel, owner, revision, closed, declaration, document }`. `session/load` replays each stored panel receipt as an `agent_thought_chunk` line in its history position and, after the whole history, sends the current state of every open panel once; `session/resume` sends that current state once and replays nothing. `_raw/panel/action` (`{ sessionId, panel, action, block?, item? }`, needs the `panelsV2` capability, idle session) runs a declared **tool** action through the normal tool path, including approval for `ask` rules and hooks, and returns `{ "operationId": string }` when it finishes; errors are `-32003` (not negotiated), `-32002` (busy), `-32004` (denied), `-32001` (unknown session), `-32602` (unknown or stale panel, invalid action, or a prompt action, which runs in the client), `-32006` (cancelled).

For a chat declaration, `_raw/panel/update` additionally carries `view: ToolViewIdentity`: repeated calls use distinct instance IDs and each starts at revision 1. `session/load` replays the corresponding immutable snapshot at each receipt's history position, reading one document at a time. The state sent after history is sidebar state only; `session/resume` does not replay earlier inline snapshots. `_raw/panel/action` additionally accepts `viewInstanceId` to bind an action to an inline snapshot; the same session and canonical owner checks apply. Peers without `panelsV2` retain receipt/confirmation text as their fallback.

Extension error codes: `-32001` unknown session, `-32002` busy, `-32003` capability missing, `-32004` unknown/denied tool, `-32005` timeout, `-32006` cancelled, `-32007` upstream failure, `-32008` duplicate registration. Standard ACP and JSON-RPC errors retain their standard meanings. Each peer owns only its own sessions and ephemeral registrations. On disconnect, raw aborts active work, closes owned MCP clients, rejects callbacks and releases child processes. Remote cancellation is best effort.

The exported `createAcpClient` helper can spawn the installed `raw --acp --stdio` child or connect to the local WebSocket endpoint, initialize, create/list/load/resume/delete sessions, prompt, observe updates, answer permissions and reverse tool calls, cancel and close. `examples/parent-agent.ts` shows the parent lifecycle. Each `createAcpServer` instance owns one peer connection; the WebSocket listener creates a fresh instance for each peer. No remote account or cloud service is required for this transport.

Peers negotiate `_meta.raw.interactions: true` for `_raw/interaction/request`. Raw sends the generic pending request (immutable declaration/document, identity, revision, effective fields and encoded-result budget) and receives a common `InteractionResponseSubmission`. The host applies the same validation/CAS as dashboard and library input. The call uses ACP request cancellation and connection signals; cancellation/disconnection ends the pending wait. It does not use `session/request_permission`. A peer without the capability receives a prompt `interaction_unavailable` tool result; ordinary ACP messages and standard plans remain supported.

`createAcpClient({ ..., onInteraction(request, signal) })` registers the callback and advertises the capability only when the callback exists. Return a scoped submit/cancel response with the request ID and revision from that request. Malformed answers are never accepted and terminate the adapter wait as cancelled. The callback receives the ACP request/connection abort signal.
